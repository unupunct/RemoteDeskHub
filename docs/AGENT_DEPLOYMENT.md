# Deploying RemoteDesk Agent

The agent is a Windows service that runs as `LocalSystem`. It enrolls once with a hub, receives a
client certificate, then heartbeats, collects metrics/inventory, and serves the hub's management API
on TCP **7444**.

## Prerequisites

- Windows 10 22H2/Windows 11 x64, with TLS 1.3 support.
- Administrative rights to install the service and firewall rule.
- Network reachability from the agent to the hub on TCP **7443**, and from the hub to the agent on
  TCP **7444**.
- A pairing package (`.rdhenroll`) created in the hub: **Computers → Enroll agent → Generate and
  save...**. The package contains the hub URL, a single-use token, the CA certificate, the hub TLS
  server certificate thumbprint and the hub console client certificate thumbprint. It does **not**
  contain private keys or passwords. Packages generated by older builds do not contain the server
  thumbprint; the agent rejects them and you must regenerate the package from the current hub.

## Install with the MSI (recommended)

```powershell
msiexec /i RemoteDesk-Agent-1.0.0-x64.msi PAIRINGPACKAGE="C:\temp\site.rdhenroll"

# Only if RDP access through Windows Firewall is explicitly required:
msiexec /i RemoteDesk-Agent-1.0.0-x64.msi PAIRINGPACKAGE="C:\temp\site.rdhenroll" ENABLE_RDP_FIREWALL=1
```

Interactive install: double-click the MSI. The `PAIRINGPACKAGE` property is optional; a silently
installed MSI without it starts the service in an unenrolled state.

What the MSI does:

- Copies the self-contained agent to `%ProgramFiles%\RemoteDesk Agent`.
- Registers the service **RemoteDeskAgent** (`LocalSystem`, automatic start, restart on failure).
- Starts the service.
- Adds an inbound firewall rule for TCP 7444 scoped to the local subnet.
- Optionally adds an inbound firewall rule **RemoteDesk Agent (Remote Desktop)** for TCP 3389,
  scoped to the local subnet, when installed with `ENABLE_RDP_FIREWALL=1`. This only opens the
  firewall port; it does **not** enable Windows Remote Desktop, add users to the Remote Desktop Users
  group, or grant sign-in rights. Enable those separately if you want RDP.
- When `PAIRINGPACKAGE` is supplied, runs
  `RemoteDeskHub.Agent.exe --pair "<file>" --data "C:\ProgramData\RemoteDesk Agent" --stage-pairing`
  after file installation. The package is copied to
  `%ProgramData%\RemoteDesk Agent\enroll.rdhenroll`; the service consumes and deletes it after
  successful enrollment.

If you copy the package after installation instead:

```powershell
Copy-Item .\site.rdhenroll "$env:ProgramData\RemoteDesk Agent\enroll.rdhenroll"
Restart-Service RemoteDeskAgent
```

The service polls for the package, so a restart is not strictly required once the file exists.

## Install from the command line (zip/self-contained folder)

The published agent folder can be used without the MSI:

```powershell
# Run from an elevated prompt, from the folder containing RemoteDeskHub.Agent.exe
.\RemoteDeskHub.Agent.exe --install --pair "C:\temp\site.rdhenroll"
```

`--install` registers the service with `sc.exe`, sets automatic startup, configures restart-on-failure,
starts it and stages the pairing package. It refuses to run without elevation (exit code 5) and never
prompts for elevation itself.

Other commands:

```powershell
.\RemoteDeskHub.Agent.exe --start
.\RemoteDeskHub.Agent.exe --stop
.\RemoteDeskHub.Agent.exe --uninstall
.\RemoteDeskHub.Agent.exe --stage-pairing --pair "C:\temp\site.rdhenroll"
.\RemoteDeskHub.Agent.exe --console            # run in the foreground with console logging
.\RemoteDeskHub.Agent.exe --version
.\RemoteDeskHub.Agent.exe --help
```

Custom data directory or ports:

```powershell
.\RemoteDeskHub.Agent.exe --install --data "D:\RemoteDesk Agent"
.\RemoteDeskHub.Agent.exe --console --port 8444 --hub https://server01:7443
```

`--pair` may be combined with `--console` for a first manual enrollment; the agent enrolls, waits for
approval and then serves management requests until stopped.

## Approve the agent

With the default policy (`agent.autoApprove = false`), the agent posts its CSR and waits. In the hub:

1. Open **Computers**.
2. Click **Agent enrollments** (the button shows the number of pending requests).
3. Review the computer name and source address.
4. Choose **Approve** to issue the certificate, or **Reject** with a reason.

If the pairing package was generated with automatic approval, the certificate is issued immediately
and the agent appears without review. The status is still visible in the enrollment list.

## Data and state

```
%ProgramData%\RemoteDesk Agent\
    agent-state.json          identity, encrypted private key/PFX, CA PEM, pending enrollment
    enroll.rdhenroll          staging location for the one-time package
    certs\                    optional certificate material
    logs\agent-YYYYMMDD.log   Serilog rolling log (14 days, 20 MB per file)
    work\                     scratch space for command execution
```

`agent-state.json` contains secrets encrypted with **DPAPI LocalMachine** scope and the entropy
`RemoteDesk.Agent.State.v1`. The file is written atomically (temporary file + rename). Protect the
folder with Administrators/SYSTEM ACLs; a local administrator can decrypt the agent key.

The agent also persists a stable `MachineId` derived from the Windows `MachineGuid`
(`HKLM\SOFTWARE\Microsoft\Cryptography`), falling back to `installation-{InstallationId}`. The hub
matches re-enrollment on `MachineId` or the persisted installation ID, so an IP change, restart or
agent reinstall keeps the same computer record, remote-access IDs and hardware history.

While the hub is unreachable, important telemetry is buffered in
`work\telemetry-queue.json` (up to 10,000 samples, written atomically). Queued samples are replayed
oldest-first after the connection returns; the agent refreshes the batch nonce and timestamp so the
hub replay guard accepts the retry.

The agent creates its own directories, so the MSI does not need to pre-create them.

## Revoke an agent

On **Computers**, select the computer and choose **Revoke agent**, then provide a reason. The hub
marks the agent revoked and rejects subsequent heartbeats/management requests. Revocation is
permanent for that identity.

To re-enroll the same computer:

1. Stop the service: `Stop-Service RemoteDeskAgent`.
2. Delete `%ProgramData%\RemoteDesk Agent\agent-state.json` (and any staged `enroll.rdhenroll`).
3. Generate a new pairing package in the hub.
4. Copy it to `%ProgramData%\RemoteDesk Agent\enroll.rdhenroll` (or reinstall with
   `PAIRINGPACKAGE=...`) and start the service.
5. Approve the new request.

The hub creates a new agent identity and certificate; history for the old identity remains in the
audit log.

## Upgrade the agent

Install a newer MSI over the existing one. The service is stopped, files are replaced and the service
is restarted. The state file, certificate and enrollment are preserved. A major upgrade removes the
old product before installing the new one; the `PAIRINGPACKAGE` custom action is skipped on upgrade.

An agent upgraded from a build that predates hub-server pinning has no
`HubServerCertificateThumbprint` in `agent-state.json`. It fails closed by design. Generate a new
pairing package from the current hub, re-enroll the agent, and approve it. Do not reuse an older
`.rdhenroll` file.

## Uninstall the agent

```powershell
msiexec /x RemoteDesk-Agent-1.0.0-x64.msi /qn
```

or **Settings → Apps → Installed apps**. The MSI stops and removes the service and firewall rule. It
does not delete `%ProgramData%\RemoteDesk Agent`; delete that folder manually to remove the identity
and logs. Revoke the agent in the hub afterwards if the computer will no longer be managed.

## Verification

On the target computer (elevated PowerShell):

```powershell
Get-Service RemoteDeskAgent
Get-Content "$env:ProgramData\RemoteDesk Agent\logs\agent-*.log" -Tail 50
Get-NetFirewallRule -DisplayName "RemoteDesk Agent (management)"
Get-NetFirewallRule -DisplayName "RemoteDesk Agent (Remote Desktop)"
```

Expected log sequence: service start, pairing package loaded, enrollment submitted, approval/cert
issued, management API listening on `https://0.0.0.0:7444`, heartbeat accepted. In the hub, the
computer changes from **Pending approval/Offline** to **Online** after the first heartbeat.

## Event log

The agent writes start/stop and fatal errors to the Windows Application log under the source
**RemoteDesk Agent**. Detailed operational logs stay in the file log to avoid flooding the event log.

## Notes and limits

- The agent never elevates itself and never accepts management connections from any certificate
  other than the hub console certificate pinned during enrollment.
- The management API binds all interfaces on the configured port (default 7444); restrict it with
  Windows Firewall and network segmentation.
- The agent must reach the hub by the exact host name/IP used in the pairing package. If DNS changes,
  regenerate the package or override with `--hub` when running in console mode.
- Agent certificates renew automatically when less than 30 days remain, using the authenticated
  `/api/agent/renew` endpoint. If renewal fails, check agent logs and hub audit entries; re-enroll only
  if the certificate has expired, the agent was revoked, or the hub CA changed.
- The shared folder uses a dedicated `C:\zzz`. The agent creates it at startup and reports a manifest;
  keep the configured `sharedFolder.path` identical on the hub and agents. It is appended to the
  runtime permitted roots only for shared-folder calls. See [SHARED_FOLDER.md](SHARED_FOLDER.md).
